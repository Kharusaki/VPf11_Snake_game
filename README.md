# Змейка-сервис: инструкция без программирования

## Что это вообще такое

Это игра «змейка», но без окна и без картинок. Программа работает как **сервер**: она молча сидит в памяти компьютера и ждёт запросов. Вы отправляете запрос — она отвечает. «Отправить запрос» здесь означает выполнить одну строку команды в терминале или нажать кнопку в браузере.

Игра одна на весь запущенный сервер. Змейка «живёт», пока запущена программа: если её остановить и запустить заново — начнётся новая пустая партия.

Никакого графического интерфейса у сервиса нет намеренно (так поставлена задача кейса). Но есть два способа смотреть на игру:

1. **Браузер** — у сервиса есть встроенная страница управления `http://127.0.0.1:8000/docs`. Это самый простой способ: там кнопки, поля и ответы показываются красиво. Дальше в инструкции он описан первым.
2. **Терминал PowerShell** — команды построчно, с примерами ответов. Это для проверки, что сервис действительно отвечает.

Сама «картинка» змейки — это текст. Поле 10×10, где `@` — голова змейки, `O` — её тело, `*` — еда, `.` — пустая клетка:

```
..........
......*...
..........
..........
..........
...OO@....
..........
..........
..........
..........
```

Змейка из трёх квадратиков смотрит вправо, еда сверху. После команды «шаг вверх» голова `@` переедет на клетку выше — по этим картинкам видно, что игра реально двигается.

1. Откройте <https://www.python.org/downloads/> и скачайте установщик для Windows.

Проверка: откройте PowerShell (клавиша Win, наберите `powershell`, Enter) и выполните:

```powershell

```

Если показалось что-то вроде `Python 3.12` или `Python 3.14` — всё готово.


Остановить сервер: нажмите в этом окне `Ctrl+C`.

## Шаг 4. Играть через браузер (самый простой способ)

1. При запущенном сервере откройте в браузере: `http://127.0.0.1:8000/docs`
2. Вы увидите список команд игры. Разверните **POST /new** → нажмите **Try it out** → **Execute**. Сервер ответил — змейка создана, в ответе есть поле `board` с картинкой поля.
3. Разверните **POST /step** → Try it out → в поле тела удалите текст и впишите, например, `{"direction": "up"}` → Execute. В ответе снова `board`, и голова `@` сдвинулась на клетку вверх.
4. повторяйте шаг 3, ведите змейку к `*`. Съели — `score` увеличится, змейка станет длиннее.
5. Ударились о край поля — в ответе появится `"game_over": true, "reason": "wall"`. Это не ошибка программы, это игра закончилась. Новая партия — снова **POST /new**.

Направление можно не менять каждый ход: достаточно `{}` — змейка продолжит движение туда же. Команду **GET /** можно выполнять в любой момент — она показывает только поле.

## Шаг 5. Проверка в PowerShell (для протокола)

Держите окно с сервером открытым. Откройте **второе** окно PowerShell.

Команды ниже используют встроенную `Invoke-RestMethod` и одинаково работают в **любой версии** PowerShell (5.1, 7.x). Разница версий ломает только передачу JSON в `curl.exe`, поэтому основной сценарий обходится без curl; заметки про него — в конце раздела.

**Подготовка — один раз. Вспомогательная команда.** Она печатает код ответа и содержимое и при успехе, и при ошибке (400/409). Вставьте весь блок целиком и нажмите Enter:

```powershell
function Req($method, $path, $body) {
  $url = "http://127.0.0.1:8000$path"
  try {
    if ($body) { $d = Invoke-RestMethod -Method $method -Uri $url -ContentType "application/json" -Body $body }
    else { $d = Invoke-RestMethod -Method $method -Uri $url }
    "{0} {1} -> OK" -f $method, $path
  } catch {
    "{0} {1} -> {2}" -f $method, $path, $_.Exception.Response.StatusCode.value__
    $d = $_.ErrorDetails.Message
  }
  if ($d -is [string]) { $d } else { $d | ConvertTo-Json -Depth 6 -Compress }
}
```

Действует, пока не закрыто окно. Дальше каждая проверка — одна строка.

**Работает ли сервер вообще:**

```powershell
Req GET /health
```

Ожидание: `GET /health -> OK` и `{"status":"ok"}`.

**Начать игру:**

```powershell
Req POST /new
```

Ожидание: `POST /new -> OK`, `"snake":[[5,5],[4,5],[3,5]]` (змейка в центре), `"score":0`.

**Сделать шаг вверх:**

```powershell
Req POST /step '{"direction":"up"}'
```

Ожидание: `POST /step -> OK`, первая клетка `snake` — `[5,4]`: голова сдвинулась на клетку вверх.

**Продолжить туда же, без смены направления:**

```powershell
Req POST /step
```

Ожидание: голова `[5,3]`.

**Посмотреть поле:**

```powershell
(Invoke-RestMethod http://127.0.0.1:8000/).board
```

Ожидание: картинка из десяти строк, голова на третьей строке сверху.

**Ошибочное направление (игра не знает «север») — ошибка 400, ход не делается:**

```powershell
Req POST /step '{"direction":"north"}'
(Invoke-RestMethod http://127.0.0.1:8000/state).snake[0] -join ","
```

Ожидание: `POST /step -> 400` и текст `direction must be up, down, left or right`; вторая команда напечатает `5,3` — змейка НЕ сдвинулась, плохую команду сервер отвергает, а не выполняет.

**Развернуться на 180° тоже нельзя** (змейка не может задом наперёд):

```powershell
Req POST /step '{"direction":"down"}'
```

Ожидание: `POST /step -> 400`.

**Довести змейку до стены** (она шла вверх, значит упрётся в верхний край):

```powershell
do { $r = Invoke-RestMethod -Method Post http://127.0.0.1:8000/step } until ($r.game_over)
"Игра окончена. Причина: $($r.reason)"
```

Ожидание: `Игра окончена. Причина: wall`.

**Шаг после конца игры — запрещён:**

```powershell
Req POST /step
```

Ожидание: `POST /step -> 409` и `game over`. Сервер честно говорит: партия кончилась, сначала `POST /new`.

**Начать заново:**

```powershell
Req POST /new
```

Ожидание: снова `[[5,5],[4,5],[3,5]]`, `score 0`.

**Схема API:**

```powershell
(Invoke-RestMethod http://127.0.0.1:8000/openapi.json).paths.PSObject.Properties.Name
```

Ожидание: `/`, `/health`, `/new`, `/state`, `/step`.

### Если всё-таки curl.exe

Команды без тела запроса универсальны в любых версиях:

```powershell
curl.exe -s http://127.0.0.1:8000/health
curl.exe -s -X POST http://127.0.0.1:8000/new
curl.exe -s -X POST http://127.0.0.1:8000/step -w "`nHTTP %{http_code}`n"
```

А вот тело JSON каждая версия PowerShell передаёт по-своему (узнать свою: `$PSVersionTable.PSVersion`):

- **5.1 / 7.0–7.2** — кавычки внутри текста экранируются: `curl.exe -s -X POST http://127.0.0.1:8000/step -H "Content-Type: application/json" -d '{\"direction\":\"up\"}'`
- **7.3+** — наоборот, без обратных слэшей: `-d '{"direction":"up"}'`; со слэшами сервер получит испорченный JSON и ответит 400.

Чтобы проверять облачную версию игры, замените `127.0.0.1:8000` на `195.19.213.59:8000`.

## Как читать ответы сервера

Ответы приходят в формате JSON — это текст вида `"поле": значение`. Самые важные поля:

| Поле        | Что значит                                                             |
|-------------|-------------------------------------------------------------------------|
| `ok`        | `true` — игра идёт; `false` — кончилась                                |
| `snake`     | клетки змейки, первая клетка — голова                                  |
| `food`      | где еда                                                                |
| `score`     | съедено еды                                                            |
| `steps`     | сколько шагов сделано                                                  |
| `board`     | текстовая картинка поля: `@` голова, `O` тело, `*` еда, `.` пусто       |
| `reason`    | чем кончилась игра: `wall` — о стену, `self` — укусила себя, `win` — заполнила всё поле (победа) |

Коды ответа (строка `HTTP ...`):

| Код | Значение                                                             |
|-----|----------------------------------------------------------------------|
| 200 | всё в порядке (конец игры — тоже нормальный ответ, смотрите `reason`) |
| 400 | команда некорректна: неизвестное направление или разворот на 180°    |
| 409 | конфликт: игра не начата или уже окончена                            |

## Правила игры

- Ходы: `up`, `down`, `left`, `right`; без тела — продолжать в том же направлении.
- Влетели в край поля — конец (`wall`). Влетели в себя — конец (`self`).
- Змейка может входить в клетку собственного хвоста, если в этот ход не ест: хвост успевает убежать. Если же в клетке хвоста лежит еда — хвост останется на месте, и это столкновение.
- Заполнили всё поле — победа (`win`), зависания нет.

## Игра в интернете (запущенный контейнер)

Сервис собран в docker-контейнер и работает на облачном мини-сервере по адресу `195.19.213.59:8000`. Правила и команды — те же, что описаны выше. Игра по-прежнему одна на сервер: если кто-то другой нажмёт `POST /new`, ваша партия начнётся заново.

### Игра прямо на сервере (SSH, bash)

Подключитесь к серверу:

```powershell
ssh root@195.19.213.59
```

На сервере обычный Linux-терминал (bash), команды PowerShell там не работают. Вставьте этот блок целиком один раз — он создаёт мини-команды игры:

```bash
U=http://127.0.0.1:8000
show() { python3 -c "import json,sys; print(json.load(sys.stdin)['board'])"; }
new-game() { curl -s -X POST $U/new | show; }
board()    { curl -s $U/ | show; }
up()       { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"up"}' | show; }
down()     { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"down"}' | show; }
left()     { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"left"}' | show; }
right()    { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"right"}' | show; }
```

Дальше играется короткими командами, Enter = один ход:

```bash
new-game    # начать партию, поле нарисовано
up          # шаг вверх
left        # шаг влево
board       # просто посмотреть поле
curl -s $U/state   # счёт, шаги, причина конца игры
```

Когда игра кончится, в поле `board` змейка стоит на месте, а `state` покажет `"game_over": true` и `"reason": "wall"` / `"self"` / `"win"`. Новая партия — снова `new-game`.

Мини-команды живут до закрытия SSH-сессии; при следующем заходе блок нужно вставить заново.

### Способ 1. Браузер — без команд вообще

Откройте `http://195.19.213.59:8000/docs` → **POST /new** → Try it out → Execute, затем **POST /step** с телом `{"direction": "up"}` → Execute. То же самое, что Шаг 4, только адрес другой.

### Способ 2. PowerShell на вашей машине: один блок — и играете мини-командами

Откройте PowerShell и вставьте **весь блок целиком**, нажмите Enter один раз:

```powershell
$u = "http://195.19.213.59:8000"
function new-game { (Invoke-RestMethod -Method Post "$u/new").board }
function board    { (Invoke-RestMethod "$u/").board }
function up       { (Invoke-RestMethod -Method Post "$u/step" -ContentType "application/json" -Body '{"direction":"up"}').board }
function down     { (Invoke-RestMethod -Method Post "$u/step" -ContentType "application/json" -Body '{"direction":"down"}').board }
function left     { (Invoke-RestMethod -Method Post "$u/step" -ContentType "application/json" -Body '{"direction":"left"}').board }
function right    { (Invoke-RestMethod -Method Post "$u/step" -ContentType "application/json" -Body '{"direction":"right"}').board }
function score    { Invoke-RestMethod "$u/state" | Select-Object score, steps, game_over, reason }
```

Дальше каждая мини-команда — это одно слово и Enter:

| Команда    | Что делает                                        |
|------------|----------------------------------------------------|
| `new-game` | начать партию (показывает поле)                    |
| `up`       | шаг вверх (показывает поле)                        |
| `down`     | шаг вниз                                           |
| `left`     | шаг влево                                          |
| `right`    | шаг вправо                                         |
| `board`    | просто посмотреть поле, не делая хода              |
| `score`    | счёт, число шагов и чем закончилась игра           |

Игра закончилась (`score` покажет `game_over: True` и `reason`) — снова `new-game`. Работает и с локальным сервером: замените в блоке адрес на `http://127.0.0.1:8000`.

### Способ 3. Терминал на самом сервере (bash)

Если вы зашли по SSH (`ssh root@195.19.213.59`), помните: там Linux и shell **bash**, команды PowerShell в нём не работают — будет `syntax error near unexpected token`. Вставьте вместо этого этот блок:

```bash
U=http://127.0.0.1:8000
show() { python3 -c "import json,sys; print(json.load(sys.stdin)['board'])"; }
new-game() { curl -s -X POST $U/new | show; }
board()    { curl -s $U/ | show; }
up()       { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"up"}' | show; }
down()     { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"down"}' | show; }
left()     { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"left"}' | show; }
right()    { curl -s -X POST $U/step -H "Content-Type: application/json" -d '{"direction":"right"}' | show; }
score()    { curl -s $U/state; echo; }
```

Игра так же: `new-game`, затем `up` / `down` / `left` / `right`.

## Docker: как контейнер получился на сервере

Путь был такой (Windows 10 сборки 19042, Docker Desktop не ставится, WSL отменён — вместо него готовый облачный сервер с Ubuntu и Docker Engine):

1. Файлы проекта (`game.py`, `main.py`, `requirements.txt`, `Dockerfile`, `.dockerignore`) загружены на сервер в папку `~/snake-service` через `scp`.

2. Сборка образа (на сервере, в папке проекта):

```bash
docker build -t snake-service:local .
```

3. Запуск контейнера: порт 8000 наружу, авторестарт после перезагрузки сервера:

```bash
docker run -d -p 8000:8000 --name snake --restart unless-stopped snake-service:local
```

Флаг `--rm` с `--restart` несовместим — для долгоживущего сервиса используется только `--restart`.

4. Проверка на самом сервере и снаружи:

```bash
docker ps                        # STATUS: Up ... (healthy)
curl -s http://127.0.0.1:8000/health   # {"status":"ok"}
```

Со своей машины: `curl.exe http://195.19.213.59:8000/health` или браузером.

Образ: `python:3.12-slim`, зависимости только из `requirements.txt` (pytest и httpx в контейнер не попали), uvicorn от пользователя `appuser` (не root), `EXPOSE 8000`, `HEALTHCHECK` каждые 30 с ходит в `/health`.

Полезные команды управления (на сервере):

```bash
docker logs snake --tail 20      # последние строки лога (ход игры, ошибки)
docker restart snake             # перезапустить контейнер
docker stop snake                # остановить (--rm не ставился, контейнер останется, но остановленным)
```

### Как обновить сервис после правок кода

Загрузить изменённые файлы, пересобрать и перезапустить:

```bash
# с Windows (файлы должны быть в пути без кириллицы — старый scp её не любит):
scp -r game.py main.py requirements.txt root@195.19.213.59:snake-service/

# на сервере:
cd snake-service
docker build -t snake-service:local .
docker rm -f snake
docker run -d -p 8000:8000 --name snake --restart unless-stopped snake-service:local
```

### Путь через WSL (не использовался, запасной вариант)

Если понадобится собирать контейнер на своей машине: Docker Desktop на сборке 19042 не ставится, Docker Engine ставится внутрь WSL2 (`wsl --install -d Ubuntu`, затем репозиторий Docker, демон через `sudo service docker start`). Команды сборки и запуска — те же, что в шагах 2–3 выше. Этот путь не проходил проверку на данной машине.
